BUG: Macierz FLU jest odwrócona (Frame.hpp:16)                                                                                                                                                                                                     
                                                                                                                                                                                                                                                        
  FLU = {{0,-1,0}, {1,0,0}, {0,0,1}}                                                                                                                                                                                                                    
                                                                                                                                                                                                                                                        
  Komentarz mówi "Column i = where frame's i-th axis lands in internal space" (internal: X=right, Y=forward, Z=up).                                                                                                                                     
                                                                                                                                                                                                                                                        
  - col0 (Forward → internal): {0,-1,0} = -Y = backward — powinno być {0,1,0}                                                                                                                                                                           
  - col1 (Left → internal): {1,0,0} = +X = right — powinno być {-1,0,0}                                                                                                                                                                               
  - col2 (Up → internal): {0,0,1} = +Z — OK                                                                                                                                                                                                             
                                                                                                                                                                                                                                                        
  Wszystkie inne ramki (NED, FRD) są poprawne. FLU ma odwrócone znaki w kolumnach 0 i 1.                                                                                                                                                                
                                                                                                                                                                                                                                                        
  Fix:                                                                                                                                                                                                                                                  
  struct FLU { static constexpr glm::mat3 M{{0,1,0}, {-1,0,0}, {0,0,1}}; };

  4. Problem: NED == FRD — identyczne macierze (Frame.hpp:15,17)
                                                                                                                                                                                                                                                        
  struct NED { static constexpr glm::mat3 M{{0,1,0}, {1,0,0}, {0,0,-1}}; };                                                                                                                                                                           
  struct FRD { static constexpr glm::mat3 M{{0,1,0}, {1,0,0}, {0,0,-1}}; };  // identyczne!                                                                                                                                                             
                                                                                                                                                                                                                                                        
  Matematycznie obie ramki mapują tak samo (forward→Y, right→X, down→-Z). Różnica jest semantyczna (world vs body), nie geometryczna. Użytkownik może się spodziewać różnego zachowania. Warto dodać komentarz albo usunąć FRD i zostawić alias.

  5. Problem: Torus — non-uniform scaling psuje geometrię (DrawPrimitives.cpp:236)                                                                                                                                                                    
                                                                                                                                                                                                                                                        
  AppendFromCache(..., GetUnitTorus(seg),
      Mat() * AxisTransform(center, axis) * glm::scale(glm::mat4(1.f), {minorR, majorR, minorR}));                                                                                                                                                      
                                                                                                                                                                                                                                                        
  Unit torus ma major=minor=1. Non-uniform scale nie rozdziela poprawnie major/minor radius — promień rury i promień pierścienia są splecione w X/Z. Przy majorR ≠ minorR rura staje się eliptyczna zamiast okrągła. Jedyne poprawne rozwiązanie to     
  generowanie torusa z właściwymi parametrami za każdym razem (bez cache) albo cache z kluczem (seg, ratio).
